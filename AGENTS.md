# Working instructions

Read `docs/findings.md` and `docs/plan.md` before continuing. `research/STATUS.txt` is historical and contains superseded conclusions; the current findings take precedence.

The user authorized patching and flashing these controllers and accepts wired recovery. That does not establish compatibility of an image. Unit1: the stock application update in `docs/stock-update.md` was flashed on 2026-10-23 and verified; the withdrawn 376-byte custom image was flashed on 2026-10-25 and left the unit in a white triple-blink reset loop with no reachable USB update mode. Two defects were confirmed (`docs/boot-failure.md`); do not reinstall that image. Unit1 recovery follows `docs/recovery.md`; identify the board before specifying any wired recovery pinout. Unit2 is a second controller: its backup was registered with `research/add_device.py`, stock was installed and confirmed physically, and the replacement custom image (2026-10-28) was installed and boots. Its AE42 stream delivered all six buttons on a Mac. Remaining: HID regression under custom, the early BLE disconnect, other modes, standby/wake, iOS background. Restore for unit2 is `flash_custom.py restore` with the current profile. Images are derived per unit from `research/devices.json` for the research workflow; `research/flash_gamebrick.py` is the one-shot end-user flasher (fingerprint-classified source, pinned OEM archive, pinned patched-application hash) and the README documents it. The repository is published as `tetramo-labs/glassly-gamebrick-cfw`.

Keep original backups immutable. Confirm unit1's copies against `docs/device-backup.json` and every unit against its backup `metadata.json`. Derive any device patch from the installed image and its actual partition map. The existing prototype matches the installed application hash, but its packaged OEM image does not match the retained flash layout. The older HID-only hook also sits after a readiness gate. The new candidate in `research/custom-prepared/` uses task/CCC/lifecycle hooks, preserves the device layout and has a guarded installer; see `docs/custom-firmware.md` and `docs/custom-install.md`. The boot audit now blocks `check` and `install` before USB access; keep `restore` usable. Do not disable protection or widen limits alone to bypass this failure. Eight regression tests reproduce both defects and verify simulated restore. A replacement image requires a fresh review and demonstrated application-independent recovery before flashing. The first two custom install attempts stopped before writes because normal storage changed. `custom_runtime.py` and `flash_stock.py` require two identical full reads and preserve the declared VM (`0x7a000..0x7bfff`), BTIF (`0x7c000..0x7cfff`) and USERIF (`0x7d000..0x7efff`) regions. Every other byte must match the current unit's pinned stock or custom template on install, including bootloader, layout and key/MAC. Restore also permits interrupted contents within the eight patch sectors. Pre-write readback, stock restore image, target and preflight report are saved before writes. `custom_baseline.py` is historical evidence for the first attempt, not the live installer. Do not erase the whole flash, overwrite calibration/pairing data, or burn chip keys/fuses as a routine flash step.

Hardware operations need explicit target checks and bounded timeouts. Stop on identity, checksum or readback mismatches. Do not weaken those checks to get past a failure.

Run the native USB helper from an interactive terminal; background administrator processes failed macOS Removable Volumes authorization. Computer-use access to Ghostty was denied; do not work around that UI restriction. Ask the user to run a concrete command when terminal credentials are needed.

Keep device dumps, OEM firmware and downloaded dependencies local and ignored by Git. Record hashes and pinned source revisions. Do not publish these artifacts or create a remote unless requested.

After a successful flash, verify normal HID operation, vendor BLE button notifications, and iOS background/locked behavior separately. Do not claim background support from a Mac BLE test.
